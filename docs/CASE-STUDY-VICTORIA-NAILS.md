# Case Study — Victoria Nails + Salon Genie

## Status

Starter case study. Requires validation and exact feature inventory before publication.

## Case Study Title

**Victoria Nails Didn't Need Another POS. It Needed Software Designed Around Victoria Nails.**

## Business Context

Victoria Nails already uses Galaxy POS for important salon functions such as customer-facing and POS-related workflows.

Exodon should not position Salon Genie as a replacement for Galaxy unless that strategy is intentionally changed later.

The current concept is:

```text
VICTORIA NAILS
      │
      ├── Galaxy POS
      │   Existing salon / POS functions
      │
      └── Salon Genie
          Custom operational Smart Layer
```

## The Gap

Off-the-shelf software cannot represent every unique operating rule or internal workflow of a specific salon.

Victoria Nails developed needs around customized operational workflows that were better served by a business-specific application layer.

## The Exodon Response

Salon Genie was developed as a custom operational layer designed around Victoria Nails.

Potential case-study areas include:
- staff operations
- shift management
- custom queue / rotation logic
- assignments
- task management
- owner visibility
- workflow automation

Only publish features that are confirmed in the current production or approved product scope.

## Key Message

**Exodon did not rebuild software that already worked. Exodon built the missing piece.**

## Public Integration Language

Until a direct supported Galaxy integration is confirmed, use:

**"Salon Genie works alongside Galaxy POS."**

Do not claim:

**"Salon Genie integrates with Galaxy POS."**

unless the technical integration is verified.

## Future Case Study Metrics

Whenever possible collect:
- admin hours saved
- reduction in missed turns / assignments
- employee workflow improvements
- task completion improvements
- manager time saved
- fewer manual steps
- operational visibility improvements
