# Product Strategy Run 001 — Exodon Profits 2.0

## Status
COMPLETE — READY FOR ARCHITECTURE HANDOFF

## Purpose
Convert the validated Exodon business model into a focused first commercial offer with clear customer fit, scope boundaries, deliverables, outcomes, and handoff requirements.

## Product Definition
Exodon Profits is a service-led **AI Business Systems** company.

Exodon helps businesses keep useful existing software, close operational gaps with custom software, and automate repetitive work with AI where the business case is clear.

Core promise:

**Keep what works. Build what's missing. Automate what slows you down.**

Primary methodology:

**DISCOVER → BUILD → AUTOMATE**

Primary product concept:

**Exodon Smart Layer**

## Initial Ideal Customer Profile

### Primary Initial Segment
Owner-operated or operationally hands-on service businesses with approximately 5–100 employees that already use several software systems but still rely on manual coordination.

### Strong Fit Signals
The business:
- uses multiple SaaS or industry systems,
- still relies on spreadsheets, texts, calls, paper, or staff memory,
- enters the same information in more than one place,
- has workflows that fall between existing systems,
- loses time or revenue because of missed follow-up or manual handoffs,
- lacks internal engineering staff,
- has a clear owner or operator who can make decisions,
- can identify measurable pain.

### Poor Fit Signals
Exodon should avoid or deprioritize prospects that:
- only need a basic brochure website,
- want a feature already solved well by inexpensive software,
- have no clearly defined business problem,
- cannot identify a decision maker,
- expect unlimited custom development for a fixed small budget,
- require unsupported or prohibited third-party access,
- want AI added only for marketing appeal,
- expect production automation without appropriate human controls.

## Initial Vertical Strategy

### Proof Vertical
Beauty / salon operations.

Use Victoria Nails + Salon Genie as the first operating proof.

### Secondary Validation Verticals
Do not fully market these at launch, but use them for targeted discovery:
- property / rental operations,
- home services,
- construction / field service,
- selected professional services.

## Commercial Offer Architecture

Exodon should initially sell three stages.

# Stage 1 — DISCOVER

## Working Offer Name
**Exodon Smart Layer Blueprint**

## Purpose
Understand how the business actually operates before proposing technology.

## Inputs
- owner / manager interviews,
- software inventory,
- workflow walkthroughs,
- sample reports / forms / spreadsheets,
- pain points,
- operational rules,
- business goals,
- constraints.

## Deliverables
The Blueprint should include:

1. Current-State Workflow Map
2. Existing Software Stack Map
3. Operational Gap Analysis
4. Manual / Duplicate Work Analysis
5. Risk and Bottleneck Map
6. Keep / Configure / Integrate / Customize Around / Build New decision matrix
7. Automation Opportunity List
8. AI Suitability Assessment
9. Prioritized Opportunity Backlog
10. Proposed Smart Layer Architecture
11. MVP Recommendation
12. Expected Business Outcomes
13. Measurement Plan
14. Implementation Options
15. High-level project range and next-step recommendation

## Required Outcome
The client should understand:
- what should stay,
- what should change,
- what should be connected,
- what should be automated,
- what is not worth building,
- what Exodon recommends doing first.

## Commercial Principle
Discovery should be a real deliverable, not only a sales call.

Pricing remains a market-validation hypothesis and should not be finalized until prospect interviews and pilot projects are completed.

# Stage 2 — BUILD

## Working Offer Name
**Exodon Smart Layer Implementation**

## Purpose
Implement the highest-value approved workflows from the Blueprint.

## Typical Scope
A Build engagement may include:
- internal web application,
- owner / manager dashboard,
- employee portal,
- customer portal,
- custom workflow module,
- reporting system,
- supported software integration,
- data import / export,
- notifications,
- role / permission system,
- workflow-specific automation.

## MVP Rule
The first implementation should target the smallest coherent solution that creates measurable operational value.

## Build Decision Rule
For every requested capability:

1. KEEP
2. CONFIGURE
3. INTEGRATE
4. CUSTOMIZE AROUND
5. BUILD NEW

Exodon should not custom-build an existing commodity feature unless there is a clear operational or economic reason.

## Default Technical Philosophy
Custom does not mean from scratch.

Prefer:
- reusable Exodon Core,
- industry modules,
- configuration,
- standard integrations,
- client-specific logic only where needed.

## Definition of Success
The Build stage should produce measurable improvement against one or more agreed operational metrics.

# Stage 3 — AUTOMATE & IMPROVE

## Working Offer Name
**Exodon Smart Operations**

## Purpose
Maintain, monitor, optimize, and extend the client's Smart Layer after launch.

## Possible Services
- hosting coordination,
- monitoring,
- bug fixes,
- security updates,
- workflow optimization,
- AI usage,
- new automations,
- reporting improvements,
- integration maintenance,
- minor enhancements,
- monthly operational review,
- usage / ROI reporting.

## Recurring Model
The recurring plan should be tied to responsibility and value, not merely “access to support.”

Potential components:
- platform / hosting responsibility,
- response level,
- monitoring,
- AI consumption,
- integration monitoring,
- included optimization capacity,
- scheduled business reviews.

Final packages and pricing require pilot validation.

## Measurable Customer Outcomes

Every engagement should define baseline and target metrics before implementation.

Possible metrics:
- administrative hours saved per week,
- reduction in duplicate entry,
- fewer missed leads,
- faster lead response,
- fewer missed assignments,
- fewer manual handoffs,
- reduced manager intervention,
- reduced error rate,
- faster task completion,
- higher customer follow-up completion,
- faster reporting,
- improved operational visibility,
- improved conversion or retention when attributable.

Do not claim ROI without a defined baseline and evidence.

## Victoria Nails Proof Plan

The Victoria Nails case study should collect at least 3–5 measurable before/after indicators.

Suggested first measurements:
- manager time spent coordinating staff / assignments,
- number of manual steps in selected workflow,
- frequency of missed or disputed turns / assignments,
- task completion visibility,
- owner time spent checking operational status.

The case study must distinguish:
- Galaxy POS responsibilities,
- Salon Genie responsibilities,
- manual processes,
- verified integration versus “works alongside.”

## Scope Boundaries

### Exodon WILL
- study workflows,
- recommend simpler alternatives when appropriate,
- build custom operational software,
- integrate supported systems,
- automate repetitive processes,
- add AI when it creates measurable value,
- design for reuse and maintainability,
- provide explicit security and approval boundaries.

### Exodon WILL NOT
- rebuild mature commodity software without justification,
- claim unsupported integrations,
- automate high-risk actions without appropriate human approval,
- bypass vendor terms or security controls,
- accept unlimited undefined scope,
- build features simply because they sound impressive,
- treat AI output as guaranteed truth,
- deploy meaningful production changes without review.

## Engagement Qualification

Before Build begins, require:

1. Named business owner / sponsor
2. Defined business problem
3. Agreed MVP outcome
4. Known current software stack
5. Confirmed data / integration feasibility where required
6. Approved requirements
7. Defined acceptance criteria
8. Defined responsibility for hosting / support
9. Defined baseline metrics when practical
10. Approved implementation scope

## Commercial Model — Validation Hypothesis

Do not publish fixed pricing yet.

### Discover

### Build

### Automate & Improve

- monitoring,
- integrations,
- AI usage,
- optimization capacity.
