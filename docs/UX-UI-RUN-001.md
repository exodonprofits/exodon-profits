# UX/UI Run 001 — Exodon Profits 2.0

## Status
COMPLETE — READY FOR DEVELOPER HANDOFF

## Purpose
Define the information architecture, responsive UX, visual hierarchy, and design-system direction for the first public version of ExodonProfits.com.

The site must explain Exodon's value in business language, demonstrate the Smart Layer concept clearly, and guide qualified prospects toward a Discovery engagement.

Core promise:

**Keep what works. Build what's missing. Automate what slows you down.**

Primary methodology:

**DISCOVER → BUILD → AUTOMATE**

Primary product concept:

**Exodon Smart Layer**

---

# 1. UX Goal

The website should answer five questions quickly:

1. What does Exodon do?
2. Who is it for?
3. How is it different from a normal software agency or SaaS company?
4. Can Exodon prove this works?
5. What should I do next?

The user should not need to understand AI architecture, APIs, LLMs, RAG, Supabase, or agent frameworks.

---

# 2. Primary Audience

Owner-operated and operationally hands-on businesses with roughly 5–100 employees that already use several software systems but still rely on manual coordination.

Primary mindset:

> “We already have software, but our business still has too much manual work.”

# 14. Discovery Intake UX

The form should feel like a guided business conversation, not an enterprise RFP.

Use multiple steps rather than one long form.

## Step 1 — Your Business
- business name
- name
- email
- phone optional
- industry
- number of employees

## Step 2 — What You Use Today
- current software
- POS
- accounting
- CRM
- scheduling
- spreadsheets
- other tools

Allow free-text additions.

## Step 3 — What Is Still Manual?
Prompt examples:
- What do employees still track manually?
- Where do you enter information more than once?
- What depends on one person remembering to do it?
- What causes missed follow-up?

## Step 4 — Business Impact
Ask:
- What does this problem cost in time?
- Does it affect revenue?
- Does it create customer delays?
- Does it create employee frustration?

## Step 5 — Desired Outcome
“What would you like to work better?”

## Step 6 — Project Readiness
- urgency
- decision maker
- budget comfort range optional
- preferred contact method

## Step 7 — Review & Submit
Summarize answers before final submission.

### Confirmation
After submission:

**Thank you. We'll review your workflow before recommending a solution.**

Do not imply instant automated proposals in MVP.

Exodon should feel:

- precise
- practical
- modern
- trustworthy
- premium
- operational
- business-focused

Avoid feeling:

- futuristic for the sake of it
- crypto-like
- cyberpunk
- generic AI startup
- playful SaaS
- overly corporate consulting

---

# 21. Logo Usage

Use the puzzle-piece concept as a subtle recurring motif.

Possible uses:
- section transitions
- process diagrams
- missing-gap visual
- hover accents
- icon background shapes

Do not overuse puzzle graphics.

The logo should remain distinct from decorative imagery.

---

# 22. Color Direction

Use the approved logo palette as the foundation.

Suggested roles:

- Deep navy: primary trust / text / navigation
- Cobalt / blue: primary interactive accent
- Teal / aqua: Smart Layer / automation accent
- White / very light neutral: content background
- Neutral gray: supporting UI

Use accent colors sparingly.

Avoid excessive gradients across the whole site.

---

# 23. Typography Direction

Use a modern sans-serif family optimized for web readability.

Recommended characteristics:
- strong headings
- compact business-style body text
- excellent mobile readability
- clear numeral rendering
- accessible weights

Typography should communicate confidence, not decoration.

---

# 24. Layout System

Recommended maximum content width:
approximately 1200–1280px.

Use:
- generous whitespace
- strong section hierarchy
- modular content blocks
- short paragraphs
- visual diagrams
- cards only when information benefits from grouping

Avoid card overload.

---

# 27. Responsive Rules

## Desktop
- side-by-side diagrams
- 3-column Discover / Build / Automate
- larger case-study comparison
- horizontal process flows where clear

## Tablet
- two-column where practical
- reduce visual density
- stack complex diagrams

## Mobile
- single-column priority
- full-width CTA buttons
- vertical process timelines
- horizontal tables converted to cards or lists
- no sideways scrolling
- touch targets at least comfortably tappable

---

# 28. Accessibility

Minimum requirements:
- semantic heading hierarchy
- keyboard-accessible navigation
- clear focus states
- labeled form controls
- sufficient contrast
- meaningful link text
- alt text for informative images
- do not rely on color alone for status
- form errors explained inline

---

# 29. Loading / Empty / Error States

Discovery form should support:

### Loading
Visible submission progress.

### Validation
Inline errors with clear correction instructions.

### Submission Error
Preserve entered data where possible.

### Success
Clear confirmation and what happens next.

---

# 30. Trust Design

The website should build trust through:

- real case studies
- clear process
- explicit scope boundaries
- supported-integration honesty
- human approval principles
- measurable outcomes
- no exaggerated AI claims

Avoid fake testimonials.

Avoid fabricated performance metrics.

# 34. UX Acceptance Criteria

The MVP UX passes when:

1. A first-time visitor can explain what Exodon does after viewing the hero and first two sections.
2. The difference between Exodon and generic SaaS is clear.
3. The Smart Layer can be understood without technical knowledge.
4. Victoria Nails demonstrates a real-world example.
5. Users can reach Start Discovery from every major page.
6. Discovery intake works comfortably on mobile.
7. No page depends on AI jargon to explain value.
8. No unsupported integration claims appear.
9. All major pages are usable on desktop, tablet, and mobile.
10. The site feels like a business systems company rather than a generic web agency.

# 36. Design Decision

**PROCEED TO DEVELOPMENT PLANNING / REPOSITORY AUDIT**

The UX is sufficiently defined for the Developer to inspect the existing Exodon repository and determine the smallest coherent implementation path.

The Developer must not begin by replacing the entire site blindly.

First:
- inspect existing site code,
- identify reusable assets/components,
- identify current framework,
- identify deployment constraints,
- compare existing content against this UX specification,
- produce a build plan before implementation.
