# Orchestrator Run 001 — Project #001

## Project
Exodon Profits 2.0

## Status
COMPLETE

## Purpose
Establish the formal project state and issue the first specialist-agent assignment using the Exodon seven-agent operating model.

## Project Objective
Reposition Exodon Profits as an AI Business Systems company that helps businesses keep useful existing software, build missing capabilities, and automate repetitive work through an Exodon Smart Layer.

## Current Phase
Research & Validation — formal validation pass.

## Approved Working Thesis
Exodon should not compete primarily as another general SaaS vendor or generic software agency. The working model is:

DISCOVER → BUILD → AUTOMATE → EXODON SMART LAYER

The Smart Layer may combine existing software, custom applications, integrations, workflow automation, and AI agents.

## Key Decisions Already Established
1. Keep useful client software rather than replacing it by default.
2. Evaluate Keep → Configure → Integrate → Customize Around → Build New.
3. Treat custom development as reusable-platform-first, not from-scratch-first.
4. Use Victoria Nails + Salon Genie as the initial operating proof/case study.
5. Defer full AI Development Studio automation until the manual seven-agent workflow is proven.
6. Use GitHub as the long-term project source of truth.

## Important Unknowns
1. Which first customer segment has the strongest willingness to pay?
2. Which problems create enough ROI to justify custom implementation?
3. How should Exodon differentiate from generic AI automation agencies?
4. What should the initial commercial offer include?
5. How should discovery, implementation, and ongoing support be priced?
6. Which parts of the Smart Layer can become reusable Exodon Core modules?
7. Which claims can be demonstrated with measurable results from Victoria Nails?

## Key Risks
- Generic AI-agency positioning
- High customer-acquisition cost
- Excessive customization
- Support burden across many unique client systems
- Building functionality available cheaply in existing SaaS
- Unsupported third-party integrations
- AI reliability/security risks
- Building internal platform infrastructure before market validation
